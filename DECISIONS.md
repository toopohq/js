# Decisions

One line per decision, newest last.

- 2026-09-23 — `spec` is a devDependency from GitHub, its commit pinned by the lockfile. Not published to npm: it never runs in a user's project, and a release pipeline would buy nothing.
- 2026-09-23 — `spec` exports raw `.ts`. Vitest and `tsc` read it as it is; a consumer that ships its code bundles it.
- 2026-09-23 — Baseline Widely Available is `lib: ["es2023"]`, and `lib` covers the language only. ES2024 as a whole is not there yet (resizable `ArrayBuffer`, early 2027); a granular entry such as `es2024.object` is added when a function needs it. Host APIs (`setTimeout`, `URL`, `TextEncoder`, `structuredClone`) are decided when a function needs one. `lib` does not track Baseline to the day: `Intl.Segmenter` passes before it becomes Widely Available on 2026-10-16, and that is accepted.
- 2026-09-23 — Delivered files are checked in their own program, `tsconfig.baseline.json`: Vite's types reference Node's, so any program that imports Vitest sees `Buffer` and `process`.
- 2026-09-23 — TypeScript 7 includes no `@types` package unless named, so `tsconfig.json` names `node`.
- 2026-09-23 — No runtime dependencies: the hook refuses a `dependencies` field on a write, CI refuses it on every pull request, since `pnpm add` in a shell bypasses the hook.
- 2026-09-23 — A Biome warning fails like an error, in CI and in the hook (`--error-on-warnings`): a warning that passes is a wish.
- 2026-09-23 — The baseline program sets `target: "es2024"`, so TypeScript's target-gated syntax checks run against the baseline, not `esnext`. The only syntax ES2024 adds, the regex `v` flag, is Widely Available since March 2026; its library is not, so `lib` stays `es2023`.
- 2026-09-23 — `pnpm check` runs Vitest after the static guards, and CI runs its own checks even when `pnpm check` fails: a case table that is red on purpose hides no other guard.
- 2026-09-23 — Stryker runs in `pnpm check`, after Vitest, over every delivered file, and breaks below 100: a surviving mutant is a missing case or code nothing needs. Scoping it to the folders a pull request touches arrives with the second function. Stryker runs the case table alone: `ignorePatterns` keeps the properties out of its sandbox, so no mutant is killed by the luck of a fast-check seed alone. `cleanTempDir` is `always`, because Vitest would collect a sandbox left by a failed run.
- 2026-09-23 — Stryker's `tsconfigFile` is empty: its sandbox rewrite of `extends` and `references` calls TypeScript's JS API, which TypeScript 7 no longer has, and no tsconfig here points outside the repository. `plugins` names the Vitest runner, which pnpm's isolated `node_modules` hides from Stryker's default lookup.
- 2026-09-23 — A benchmark is `cases.bench.ts`: Vitest 5 runs `*.bench.ts` in a benchmark project of its own and `vitest run` never collects it, so the name needs no config. It holds the workload alone, `tooling/gate.ts` the rest: the case table without its throws, in columns so a call spreads nothing, a hundred passes per iteration, since Windows times in 100 ns ticks. The measure is the median: over ten runs it spread 4 %, the mean 24 %. The same loop around a no-op is 30 % of an iteration (12.4 µs of 41.8 µs on mains, 19.3 of 64.7 on battery, medians of ten runs; 36 % with the spread).
- 2026-09-23 — The no-regression gate is `pnpm bench`, local, an A/B in one run: `bench.compare` times the `index.ts` of `origin/main`, imported from a temporary copy `git show` writes, against the branch's, in five rounds, the order alternating, and fails when the median of the five branch-to-main ratios passes 1.11. The machine, its power and Node cancel out, and no baseline is stored, so deleting `bench.json` bypasses nothing. Thirty A/A runs, the same code on both sides, fifteen on mains and fifteen on battery: 28 within 1.3 %, then 1.031 and 1.099, both on mains. The 1.099 held over three rounds of alternating order, a lasting asymmetry rather than a disturbance, likely the JIT. 11 % is that 9.9 % plus a margin, about 16 % of the function's own time. Thirty more A/A runs failed none (widest 1.0096); a regression of 20 % of the function's own time, every eighth call computed twice, measured +13.7 % and failed thirty of thirty (lowest 1.129). A function main does not have yet is recorded without comparison. Known ceilings: each version may be up to 11 % slower than the one before; the copy resolves no relative import, which a function importing another will need.
- 2026-09-23 — `bench.json` serves publication alone: `{ sha256, p50 }`, the median of the branch's five medians, per call in nanoseconds, which holds when the case table grows. It is written when its digest is not that of `index.ts` and the gate passed, so a rerun leaves the tree clean. CI runs no benchmark, and comparing the pull request's figure with main's there would compare two runs: a power change alone moved the median 55 %. `tooling/figures.test.ts` checks every `bench.json` carries the sha256 of its `index.ts`, so the delivered file cannot change without a figure `pnpm bench` recorded, short of a digest written by hand, which no guard closes while benchmarks stay out of CI. `ignorePatterns` keeps that test out of Stryker's sandbox, where `index.ts` is instrumented.
- 2026-09-23 — `string/truncate` keeps its two-bound surrogate test: the masked `(unit & 0xfc00) === 0xd800` measured a tie, 49.2 µs against 49.3 µs over ten runs each, inside the noise.
- 2026-09-23 — `tooling/delivered.test.ts` guards what a user copies. A function folder holds exactly its six files; `meta.ts`, the seventh, joins the list with the emitter that reads it. `index.ts` opens on `// js/<domain>/<name>` and names no copyright, licence or SPDX identifier; it imports nothing, which widens to a declared Toopo dependency when a function first needs one; it carries no `///` directive, no `@ts-` pragma and no `declare`, each of which steps outside the baseline program (a declared `process.getBuiltinModule('node:fs')` compiles against it), and no `Stryker` or `biome-ignore` comment, which would switch off the mutation score or the size rules; and under 10 % of its non-blank lines after the address are comment lines, every line of a `/* … */` block counting as one. A regex over the text, since TypeScript 7 has no JS API to parse with: it also refuses the word in a comment or a string, takes a `/*` inside a string or a regex for a comment, erring strict, and does not count a trailing comment. `tsc` already refuses a computed `globalThis['req' + 'uire']` (TS7053); `new Function('return process')()` passes both, a deliberate bypass that only review catches, and refusing `Function` would only move it to `[].map.constructor(…)`. `ignorePatterns` keeps every `tooling` test out of Stryker's sandbox: none can kill a mutant, and one that reads `index.ts` would read it instrumented.
- 2026-09-23 — Everything under `functions/` is MIT-0, in `functions/LICENSE`, and the rest of the repository MIT: a copied function owes no attribution, and the delivered file carries no licence header, only its address.
- 2026-09-24 — The gate compiles the loop once per side. Closures from one site share V8's feedback, so main's and the branch's loops were one call site reaching two versions: V8 deopted it on `wrong call target` and never inlined `truncate`. `cases.bench.ts` now exports `load` and passes it to `gate`, called at its top level; `gate` registers the test and times the branch through that typed `load`, which nothing else calls, and main through the `load` of the bench file imported again under `?main`, a second module and a second compilation, whose own call to `gate` registers nothing: it is evaluated inside the running test, and `gate` returns when `TestRunner.getCurrentTest()` is set. Traced: no deopt, each side inlines its `truncate`. Thirty A/A runs, fifteen on mains and fifteen on battery, came within 0.985 and 1.0125, and twenty-four more while developing within 1.0217, the widest under a V8 trace; the threshold falls from 11 % to 3 %. Every sixteenth call computed twice measured +10.3 % to +14.8 % and failed thirty of thirty (1.103 would have passed at 11 %); a slice computed again when `cut` is a multiple of 8 measured +0.6 % to +4.5 %, median +2.1 %, and failed six: each version may be up to 3 % slower than the one before. A process can keep one side in a slow JIT state for all five rounds, which the median does not reject: 0.65 in one A/A run, possibly beside a stopped run still going, and 0.882 and 1.137 in the second regression. The figure falls from 21.7 ns to 15.4, the call now inlined; one recording right after a switch to mains read 17.6, three more 15.3 to 15.4. Remeasured after the review dropped `?branch`: traced, no `wrong call target` on the loop, and each side inlines its own `truncate`; fifteen A/A on mains came within 0.9789 and 1.0187, median 1.000, three of them outside the earlier band, each held through its five rounds, the per-process state above, all within 3 %.
- 2026-09-24 — The emitter serves a function as three files, `js/<domain>/<name>.ts`, `.js` and `.json`, its record: `{ address, version, summary, exports, emissions: { ts, js }: { path, sha256 }, dependencies }`, each `path` from the registry's root. Only the current version is served; a client verifies what it fetched against the digest. The record's type is `spec`'s `ServedRecord`, moved there once `toopo add` read it, and the emitter types its record by it. `exports` names what `index.ts` exports, so the client can print the import line: the keys of the module imported, sorted, since Node sorts a module's keys and Vitest's runner keeps source order, so the guard would check a record other than the one deployed. A type leaves no key, so a type-only function would serve `exports: []`, and a default export `['default']`, which no import line can name: the guard refuses both, and the emitter learns a type's name with the first type-only function, as it learns to emit `.ts` alone. The figure stays out of the record while nothing reads it there.
- 2026-09-24 — The `.js` is `index.ts` through Node's `stripTypeScriptTypes`, which blanks the types in place, then `biome format`: it keeps the address header, the comments and the blank lines, and `erasableSyntaxOnly` makes stripping enough. `tsc` drops the header when it precedes an erased `type`, drops blank lines and indents by four. `stripTypeScriptTypes` is experimental in Node 24 and warns; Biome erases any change in whitespace, and `tooling/emit.test.ts` checks that the emitted `.js` exports the names of `index.ts` and returns or throws what it does on every input of the case table, so a change in behaviour fails CI. CI pins Node 24, so the move to 26 and its stripper goes through a pull request, like a Biome bump. A type-only function will emit `.ts` alone; the emitter learns it with the first one.
- 2026-09-24 — `meta.ts` holds what the folder does not already say: `version` and `summary`. The address is the folder, the emissions are computed, and `dependencies` is empty while `index.ts` imports nothing. The summary is not read from `spec`: Node strips no types under `node_modules`, so no Node script reads its raw `names.ts`, and `spec` names a concept where the summary describes this implementation. The emitter imports `meta.ts` dynamically, so knip takes it as an entry.
- 2026-09-24 — `tooling/delivered.test.ts` also refuses an `as` type assertion in a delivered file. `PLAN.md` claimed a lint rule enforced this and none did for `as`: Biome refuses `any` and a non-null assertion with stable rules, `noExplicitAny` and `noNonNullAssertion`, and `tsc` refuses `<T>x` under `erasableSyntaxOnly`, but Biome's `noUnsafeTypeAssertion` is a Nursery rule: unstable, and a version bump could drop it and switch the guard off in silence. The check reads the file through Node's `stripTypeScriptTypes`, which the emitter already runs: an `as` it blanks is type syntax, and one in a comment, a string or an `export { a as b }` survives it. A regex over the text, comment lines dropped first, missed an assertion after a `/*` inside a string, and one on the line a block comment closes. `as const` counts, since it asserts; `satisfies` does not, since it checks a type rather than asserting one. Proven by injecting `as number` into `string/truncate`: green before, red after.
- 2026-09-24 — CI refuses a pull request touching more than one function folder. `PLAN.md` names it as the mechanical proxy for one task per session, `STATE.md` being private and unreadable from CI. It is born green and cannot fire while the catalogue holds one function; the event it catches is a session that drifts into two, and the cost of nobody watching is the context sprawl the session protocol exists to prevent. `functions/LICENSE` is out of its population: the pattern matches a path three segments deep. It diffs `base...head`, from where the branch left main, since `base..head` counts every folder main gained since then against the branch. A rename counts as its destination alone: moving a function is one task.
- 2026-09-24 — CI deploys every push to `main` to Cloudflare Pages once `pnpm check` passed: `pnpm emit`, then `wrangler pages deploy` of `dist/` to the project `toopo-js`, which holds `toopo.dev`; `toopo` is the previous site's, and each catalogue will deploy its own tree. Not Cloudflare's Git integration: the deployment runs the Node and pnpm that CI runs, and nothing `pnpm check` refused reaches the site. Wrangler runs through `npx`, pinned, rather than as a devDependency every install would carry for one step on `main`; `pnpm dlx` refuses it, pnpm 12 running no build script it was not told to. `_redirects` serves each record at its address, one static rule per function: Pages applies a redirect even over an existing asset, and a placeholder matches a dot, so `/js/:domain/:name` would send `truncate.ts` to `truncate.ts.json`. Pages takes 2,000 static rules. Measured on a preview: Pages serves `.ts` as `video/mp2t` and names no charset on `.js`, which a browser needs to show `…`. `_headers` sets `.ts` to `text/plain`, since no TypeScript type is registered, and `.js` to `text/javascript`, both `charset=utf-8`, through `/js/*.ts` and `/js/*.js`: a splat with a suffix, which Pages' documentation does not mention and which works. `.json` stays `application/json`, UTF-8 by definition. The step then compares every file, and each record at its address, with what the deployment serves, and checks the content type of every `.ts` and `.js`, on the deployment's own URL: the alias `preview.toopo-js.pages.dev` still served the previous `.js` a minute after a deployment, while a new deployment's URL served the new tree within a second. Proven on previews: it passes on the tree, and fails on a deployment without `_headers` and on a record the deployment does not serve. Wrangler runs inside `dist/`: from the root it takes the catalogue's `functions/` for Pages Functions, runs esbuild over every `.ts` there, fails the deployment on one it cannot parse, and would deploy a Worker for an `onRequest` export. The step takes the URL of a production deployment alone, so a project whose production branch is not `main` fails rather than passing on a preview. Each request retries, since wrangler stops waiting once the deploy stage has started, not finished.
